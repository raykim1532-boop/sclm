# 구글 캘린더 연동 설정 (SCLM)

앱이 구글 캘린더와 연동하려면 **본인 구글 클라우드에서 OAuth 앱**을 한 번 만들어야 합니다.

## 필요한 값 (앱에 고정)
- 승인된 JavaScript 원본: `https://raymond-scheduler.pages.dev`
- 승인된 리디렉션 URI: `https://raymond-scheduler.pages.dev/api/google/callback`
- 스코프: `https://www.googleapis.com/auth/calendar`

## 단계
1. https://console.cloud.google.com → 프로젝트 생성/선택
2. **API 및 서비스 → 라이브러리 → "Google Calendar API" → 사용 설정**
3. **OAuth 동의 화면**: User type = 외부(External) → 앱 이름(SCLM), 지원 이메일, 개발자 이메일 입력 → 저장
   - **중요:** 설정 후 **"앱 게시(PUBLISH APP)" → 프로덕션**으로 전환하세요. (테스트 모드는 리프레시 토큰이 7일마다 만료됩니다.)
   - 프로덕션이라도 미인증 앱이라 로그인 시 "확인되지 않은 앱" 경고가 뜨는데, 본인 앱이므로 **고급 → 이동**으로 진행하면 됩니다.
4. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - 승인된 JavaScript 원본 / 리디렉션 URI: 위 값 입력
   - 만들기 → **클라이언트 ID / 클라이언트 보안 비밀** 복사
5. Cloudflare 시크릿 등록 (web/ 폴더에서):
   ```
   npx wrangler pages secret put GOOGLE_CLIENT_ID --project-name raymond-scheduler
   npx wrangler pages secret put GOOGLE_CLIENT_SECRET --project-name raymond-scheduler
   ```
6. 앱 새로고침 → 설정 → "구글 캘린더 연동" → **구글 캘린더 연결** → 로그인/권한 허용 → "연결됨"

연결이 확인되면 2단계(양방향 동기화)를 붙입니다.

## 구글 시트 읽기 전용 동기화 (업무 트래커)

업무 리스트(구글 시트)를 **읽기 전용으로 앱에 가져옵니다(시트→앱).** 시트에는 **아무것도 쓰지 않으므로** 수식·서식·다른 탭이 안전합니다. 할 일은 시트에서 관리하고, 동기화하면 앱과 매일 아침 알림에 반영됩니다.

> ⚠️ 과거에는 양방향(앱→시트 쓰기)이었으나, 제목행·수식·여백열이 있는 실사용 시트를 훼손하는 문제로 **읽기 전용으로 전환**했습니다.

### 준비 (스코프 확대 → 재동의 1회 필요)

시트 동기화는 캘린더 스코프에 더해 **`https://www.googleapis.com/auth/spreadsheets`** 스코프가 필요합니다. 기존에 캘린더만 연결돼 있었다면 아래를 진행하세요.

1. https://console.cloud.google.com → **API 및 서비스 → 라이브러리 → "Google Sheets API" → 사용 설정**
2. **OAuth 동의 화면 → 데이터 액세스(범위)** 에 `.../auth/spreadsheets` 스코프 추가(테스트 모드면 본인 계정이 테스트 사용자로 등록돼 있어야 함)
3. 앱 → 설정 → **구글 캘린더 연동 → 연결 해제 → 다시 연결** (새 동의 화면에서 시트 권한까지 허용). *새 클라이언트 ID/시크릿은 필요 없고, 동의만 다시 받으면 됩니다.*

### 사용

1. 앱 → 설정 → **"구글 시트 동기화"** 카드
2. 동기화할 **구글 시트 URL** 붙여넣기 → **시트 저장**
3. **지금 동기화** (또는 "자동 동기화" 체크 시 앱 열 때 + 15분마다)

### 동작 규칙

- **시트에는 절대 쓰지 않습니다.** 값만 읽어 앱 `todos`를 시트 기준으로 교체합니다(캘린더 연동용 `googleId`는 id로 보존).
- 열은 **고정 위치**로 매핑합니다(0-index): `0 No · 1 등록일 · 2 마감(예정)일 · 3 완료일 · 4 담당자 · 5 대분류 · 6 세부채널 · 7 우선순위 · 8 진행상태 · 9 점검필요 · 10 업무내용 · 11 진행사항 · 13 비고`. 14·15열(D-Day·소요일수)은 수식이라 읽지 않습니다.
- **구조 가드**: 헤더 행(5열=`대분류`, 10열=`업무내용`)을 찾지 못하면 **가져오기를 중단**하고 앱 데이터를 건드리지 않습니다.
- 각 할 일 id는 `등록일+업무내용` 해시로 안정적으로 부여됩니다(시트 No가 재정렬돼도 유지).
- **대분류**는 앱 카테고리 이름과 매칭되며, 없는 이름이면 새 카테고리를 자동 생성합니다.
- 대상 탭은 `gid`로 지정합니다(예: 업무리스트 탭).
